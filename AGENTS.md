# Agent Rules

If `~/.agents/AGENTS.md` exists, read it and follow it.

## Battlezone runtime and validation

Battlezone is a native winit/wgpu window application that draws vector meshes directly on the GPU. The CPU raster renderer supports headless tests and media generation. The Kitty renderer and terminal keyboard backend have been removed. These repo-specific instructions supersede older terminal smoke-test notes in shared guidance.

Run `make ci` for formatting, all-target tests, and warnings-as-errors Clippy. Run interactive smoke tests in a graphical desktop session with `cargo run --release`: verify visible attract rendering, Enter starting gameplay, held-key releases, resize handling, focus-loss input clearing, and Escape or window-close exit. A PTY or successful process startup alone does not prove GPU presentation.

The published Homebrew formula pins the wgpu source commit; its optional HEAD build follows `develop`. Keep the README installation commands and tap formula aligned when changing release or branch selection. Use `battlezone --help` and `battlezone --version` for display-free installed-command checks.

Documentation media is generated by `make readme-media` from `examples/generate_readme_media.rs`. Update that maintained source before regenerating PNG/GIF assets. Media shows game frames without terminal branding or simulated window chrome.

## Release contract

The release targets are `aarch64-apple-darwin` (macOS ARM64) and `x86_64-pc-windows-msvc` (Windows x86-64). Keep the workflow matrix, README download names, Cargo version, and RELEASING.md aligned. A `vX.Y.Z` tag must match the binary's `--version`. Both builds and extracted-archive checks must pass before publishing the two archives and SHA-256 manifest.

Run `make workflows` with actionlint installed after workflow changes. CI tests macOS ARM64, Windows x86-64, and Linux; graphical rendering still needs a live window check. Homebrew updates are separate from GitHub Release publication.
